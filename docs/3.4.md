# 龍蝦騎士社區｜人與組織需求文檔

---

# 1. 項目背景

龍蝦騎士社區是面向 AI 落地生態中的龍蝦騎士 / FDE、咨詢公司、企業客戶及相關從業者建立的社區與協作平台。

整個產品後續會逐步承載：

* 龍蝦騎士 / FDE 人才
* 咨詢公司
* 企業客戶 / 需求方
* 企業需求
* 項目承接
* AI 項目交付
* Solution 沉澱
* 生態協作

但第一階段暫不進入「需求與交付」。

第一階段首先需要解決：

> **平台裡有哪些人、有哪些公司，以及這些人和公司之間是什麼關係。**

因此第一階段以「建立人與組織」為核心，優先完成：

* User 帳號體系
* 多身份體系
* 龍蝦騎士 / FDE 體系
* 咨詢公司體系
* FDE 與咨詢公司的組織關係
* 龍蝦學院
* 問題廣場
* 龍蝦社區
* 管理後台

為第二階段「需求與交付」建立基礎。

---

# 2. 第一階段核心目標

完成龍蝦騎士社區的基礎產品結構及供給側建設，使首批：

* 龍蝦騎士 / FDE
* 咨詢公司
* 咨詢公司 Owner / Admin

可以正式進入平台。

同時提前建立可擴展的身份模型，為第二階段的：

> **企業客戶 / 需求方（內部角色：B 端 3 號仔）**

預留身份能力。

第一階段完成後，平台至少能回答：

> 這個 User 是誰？

> 他擁有哪些身份與公司內角色？

> 他是不是龍蝦騎士？

> 他是不是某家咨詢公司的 Owner / Admin？

> 這家公司是誰？

> 哪些龍蝦騎士屬於這家公司？

---

# 3. 第一階段成功標準

第一階段至少需要跑通以下四條核心流程。

## 3.1 User 進場

```text
進入龍蝦騎士社區
↓
註冊 / 登入
↓
建立 User
↓
完善個人資料
↓
進入社區
```

---

## 3.2 龍蝦騎士建立

```text
普通 User
↓
選擇「成為龍蝦騎士」
↓
查看龍蝦騎士介紹
↓
提交相關資料
↓
平台 / 運營確認
↓
後台設置龍蝦騎士身份
↓
建立 FDE Profile
```

第一階段暫不建設：

* 考試
* HRC 考核
* 等級
* 自動認證

正式龍蝦騎士認定規則待業務確認後再補充。

---

## 3.3 咨詢公司入駐

```text
User
↓
選擇「咨詢公司入駐」
↓
提交公司資料
↓
平台審核
↓
審核通過
↓
建立 Company Profile
↓
申請人成為該公司的 Owner
```

---

## 3.4 FDE 與咨詢公司建立關係

第一階段只支持 FDE 主動申請加入公司，不建設公司主動邀請 FDE。

### FDE 主動加入

```text
龍蝦騎士
↓
搜尋咨詢公司
↓
查看公司 Profile
↓
申請加入
↓
公司 Owner / Admin 處理
↓
通過
↓
建立 FDE × Company 關係
```

第一階段約束：

* 龍蝦騎士同一時間只能有 1 個待處理加入申請
* 龍蝦騎士同一時間最多有 1 個正式所屬咨詢公司
* 如果已正式所屬某家公司，不可再申請加入其他公司
* 只有已通過審核的咨詢公司可以被申請加入
* 公司主動邀請 FDE 暫不做
* 活動合作、教程共創、跨公司項目合作等弱關係暫不建模

# 4. 核心產品原則

## 4.1 先有 User，再有身份

用戶首先註冊的是：

> **龍蝦騎士社區 User 帳號**

而不是註冊時直接固定為：

* 龍蝦騎士
* 客戶

身份是在 User 基礎之上逐步增加；公司 Owner / Admin 則是在 User 與 Company 的組織關係上授予。

---

# 5. 一個 User 可以擁有多個身份

身份之間不互斥。

系統應採用：

```text
User
├─ 普通用戶
├─ 客戶 / 企業需求方
├─ 龍蝦騎士 / FDE
└─ 未來其他身份
```

咨詢公司的 Owner / Admin 是公司內角色，屬於 User 與 Company 的組織關係，不是全局 User Identity。

例如同一個 User 可以同時是：

```text
User A
├─ 龍蝦騎士 / FDE
├─ ABC Consulting Owner / Admin
└─ 企業客戶 / 需求方
```

因此禁止使用：

> `role = FDE / CompanyAdmin / Customer`

這種互斥式單 Role 模型。

---

# 6. 客戶 / 企業需求方身份

客戶即未來在平台提交企業需求的人。

內部業務角色名稱：

> **B 端 3 號仔**

正式產品 UI 建議使用：

> **企業客戶**

或：

> **企業需求方**

第一階段只預留此身份，不開放完整需求能力。

第二階段才正式啟用：

* 提交需求
* 補充需求
* 查看需求狀態
* 查看售前進度
* 反選咨詢公司
* 查看項目進度
* 驗收

因此第一階段不用做「客戶中心」或「需求中心」。

---

# 7. 咨詢公司是一級業務對象

咨詢公司不能只是 User Profile 裡的一個「公司名稱」。

平台中需要存在獨立：

> **Company**

Company 擁有自己的：

* 公司 Profile
* 公司 Owner / Admin
* 龍蝦騎士
* 公司狀態
* 公司與 User 的組織關係

---

# 8. 第一階段不寫死龍蝦騎士考核規則

目前龍蝦騎士：

* 如何考試
* 如何考核
* 是否有等級
* 如何認證

仍未最終確定。

因此第一階段暫不建設：

* 在線考試
* 題庫
* HRC 考核
* Lv.1～Lv.4
* 考核進度
* 考試結果
* 等級管理
* 自動認證
* 認證中心

第一階段只保留：

> **龍蝦騎士身份管理能力。**

---

# 9. 第一階段角色

## 9.1 普通用戶

完成註冊的基礎 User。

可以：

* 瀏覽首頁
* 查看教程
* 參與問題廣場
* 瀏覽龍蝦社區
* 完善 Profile
* 申請成為龍蝦騎士
* 發起咨詢公司入駐

---

## 9.2 客戶 / 企業需求方

代表企業提出業務需求的人。

第一階段：

> **僅預留身份模型，不提供獨立業務功能。**

第二階段正式啟用。

---

## 9.3 龍蝦騎士 / FDE

經平台確認具有龍蝦騎士身份的 User。

可以：

* 展示龍蝦騎士身份
* 建立 FDE Profile
* 展示能力與經驗
* 申請加入咨詢公司
* 參與社區內容建設

---

## 9.4 咨詢公司 Owner / Admin

代表咨詢公司進行平台操作的 User。

可以：

* 管理公司 Profile
* 管理公司龍蝦騎士
* 處理加入申請
* 解除組織關係

咨詢公司 Owner / Admin 可以同時是：

> **龍蝦騎士 / FDE**

---

## 9.5 平台管理員

負責：

* User 管理
* 龍蝦騎士管理
* 咨詢公司審核
* 咨詢公司管理
* 內容審核
* 平台基礎治理

---

# 22. 評價與信用

由於尚未發生正式需求與交付，第一階段暫時不建立複雜信用算法。

可先展示：

* 龍蝦騎士身份
* 社區貢獻
* 教程貢獻
* 內容貢獻
* 違規情況

* 項目數量
* 項目完成率
* 客戶評價
* 咨詢公司評價
* 履約情況
* 交付信用

# 24. 龍蝦騎士管理

咨詢公司 Owner / Admin 可以管理與公司存在正式所屬關係的龍蝦騎士。

第一階段核心能力：

```text
龍蝦騎士管理

├─ 我的騎士
├─ 加入申請
└─ 解除關係
```

---

## 24.1 我的騎士

展示：

* 頭像
* 姓名
* FDE Profile
* 能力方向
* 加入公司時間
* 關係狀態

## 24.2 邀請騎士

---

## 24.3 加入申請

```text
龍蝦騎士申請加入
↓
公司 Owner / Admin 查看申請
↓
通過 / 拒絕
↓
通過後建立正式組織關係
```

公司 Owner / Admin 可以查看：

* 申請人
* FDE Profile
* 能力
* 經驗
* 申請時間

# 37. 第一階段最終產出

第一階段最終需要形成平台第一批可被後續業務使用的：

> **人 + 身份 + 公司 + 能力 + 組織關係**

具體包括：

### 人

平台知道 User 是誰。

### 身份

平台知道一個 User 擁有哪些身份：

* 客戶 / 企業需求方
* 龍蝦騎士 / FDE

公司 Owner / Admin 是公司內角色，不屬於全局身份。

### 公司

平台知道有哪些正式入駐的咨詢公司。

### 能力

平台知道龍蝦騎士：

* 擅長什麼
* 做過什麼
* 有哪些案例

### 關係

平台知道：

> 哪個 FDE 屬於哪家咨詢公司。

---

# 38. 第一階段核心判斷標準

第一階段不是以：

> 「做了多少個頁面」

判斷是否完成。

而是平台是否真正建立了五樣東西：

> **人**

這個 User 是誰。

> **身份與公司內角色**

他是客戶、FDE，是否在某家公司擁有 Owner / Admin 公司內角色。

> **組織**

這家公司是誰。

> **能力**

這個 FDE 能做什麼。

> **關係**

這個 FDE 和哪家公司存在正式關係。

當這五個基礎成立後，第一階段「建立人與組織」完成。

第二階段再基於這套結構開始：

> **企業需求 → 咨詢公司承接 → 售前 → 客戶反選 → FDE 交付。**
